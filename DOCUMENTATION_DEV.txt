Projet   : CarteRose
Stack    : Laravel 13 / PHP 8.3 / Blade / Vite / Spatie Permission / JWT / DomPDF / QRCode
Objectif : Gestion des cartes roses, plaques d'immatriculation, véhicules,
           propriétaires et stocks de produits par poste de travail.

Dernière mise à jour : 2026-10-15


--------------------------------------------------------------------------------
1. PRÉSENTATION
--------------------------------------------------------------------------------

CarteRose est une application web (session Blade) pour les services
d'immatriculation / cartes roses. Elle permet de :

  - authentifier les agents et administrateurs ;
  - sélectionner un poste de travail (contexte de session) ;
  - enregistrer des véhicules avec propriétaire (existant ou nouveau) ;
  - générer automatiquement une plaque et une carte rose à la création ;
  - imprimer la carte rose (PDF) avec QR code ;
  - gérer les stocks de produits par poste (approvisionnements) ;
  - administrer utilisateurs, rôles et permissions.

Une API JWT minimale existe aussi (login / logout / refresh / me).


--------------------------------------------------------------------------------
2. PRÉREQUIS
--------------------------------------------------------------------------------

  - PHP >= 8.3 avec extensions Laravel habituelles (pdo, mbstring, openssl, etc.)
  - Composer 2.x
  - Node.js + npm (assets Vite)
  - SQLite (défaut .env.example) ou MySQL/PostgreSQL


--------------------------------------------------------------------------------
3. INSTALLATION LOCALE
--------------------------------------------------------------------------------

  1) Cloner / se placer dans le projet
       cd /var/www/CarteRose

  2) Dépendances PHP + frontend
       composer install
       cp .env.example .env
       php artisan key:generate
       npm install

  3) Base de données
       # SQLite (rapide) :
       touch database/database.sqlite
       # ou configurer DB_* dans .env pour MySQL

       php artisan migrate
       php artisan db:seed

     Si les migrations sont réinitialisées sans exécuter les seeders, se connecter
     avec un compte administrateur existant. En l'absence totale de poste de
     travail, l'administrateur est automatiquement dirigé vers l'étape de création
     du premier poste avant d'accéder au tableau de bord.

  4) Lancer en développement
       composer run dev
       # équivalent : serveur + queue + logs (pail) + vite en parallèle

  Ou séparément :
       php artisan serve
       npm run dev

  Script tout-en-un alternatif :
       composer run setup

4. ARCHITECTURE
--------------------------------------------------------------------------------

Organisation type Laravel avec couche Services + Contracts.

  app/
    Contracts/          Interfaces des services (DI)
    Enums/              Messages d'auth, etc.
    Http/
      Controllers/      Contrôleurs fins (délèguent aux services)
      Middleware/       Auth session, JWT, poste sélectionné
    Models/             Eloquent
    Providers/          AppServiceProvider, RouteServiceProvider
    Services/           Logique métier
    Support/            Helpers (ex. CurrentPostTravail)
    Traits/

  bootstrap/app.php     Routing + alias middleware + exceptions Spatie
  routes/web.php        Application principale (session)
  routes/api.php        Auth JWT minimale
  resources/views/      Blade (layouts, CRUD, auth, carte)
  database/migrations/  Schéma
  database/seeders/     Rôles, postes, users, produits, stocks


Flux typique requête web
------------------------
  Request
    -> AuthMiddleWare (session connectée)
    -> post.selected (poste ou dashboard global admin)
    -> permission / role (Spatie)
    -> Controller
    -> Service
    -> Model / DB
    -> View ou redirect


--------------------------------------------------------------------------------
5. MODÈLES & RELATIONS PRINCIPALES
--------------------------------------------------------------------------------

  User
    - rôles Spatie (admin, chef_poste, agent, lecteur)
    - many-to-many PostTravail (pivot is_default)

  PostTravail
    - hasMany : Vehicule, CarteRose, Plaque, PostProduit, Approvisionnement
    - belongsToMany : User

  Propietaire  (orthographe historique du projet : "propietaire")
    - hasMany Vehicule
    - types : Entreprise | Personne Physique | Organisation | Autres

  Vehicule  (SoftDeletes)
    - belongsTo Propietaire, PostTravail
    - hasOne Plaque
    - hasMany CarteRose

  Plaque
    - belongsTo Vehicule, PostTravail
    - code unique (immatriculation), statut (ex. attribuee)

  CarteRose
    - belongsTo Vehicule, PostTravail, User
    - numero unique, qr_token (UUID), statut (ex. active)
    - format auto-généré : DGRK/XXXX/{vehicule_id}/ddmmyyyy

  Produit
    - catalogue global (plaque, carte rose, etc.)

  PostProduit
    - stock d'un Produit pour un PostTravail (quantite)

  Approvisionnement
    - entrée de stock vers un poste (création -> confirmation)


Contexte "poste courant"
------------------------
  App\Support\CurrentPostTravail
    - SESSION_POST_ID  : id du poste actif
    - SESSION_GLOBAL   : mode dashboard global (admin)
    - used par VehiculesService::all() pour filtrer les listes


--------------------------------------------------------------------------------
6. SERVICES MÉTIER
--------------------------------------------------------------------------------

  VehiculesService (VehiculeServiceInterface)
    store()
      - valide véhicule + option création propriétaire
      - exige un post_travail (session ou défaut user)
      - transaction DB :
          * crée Vehicule
          * crée Plaque (code = immatriculation, dédoublonnage -{id})
          * crée CarteRose (numero fourni ou généré, qr_token UUID)
          * décrémente jusqu'à 2 PostProduit du poste (stock > 0)
    update()  — met à jour véhicule + code plaque
    show/all/delete/edit/create

  ProprietaireService
    - CRUD propriétaires, recherche par téléphone (getByTel)

  CarteService
    - logique cartes roses / impression

  AuthService / AuthServiceWeb
    - auth API JWT vs auth web session


--------------------------------------------------------------------------------
7. AUTHENTIFICATION & SÉCURITÉ
--------------------------------------------------------------------------------

Web (session)
-------------
  Middleware : App\Http\Middleware\AuthMiddleWare
  Connexion avec email, téléphone ou nom ; "Se souvenir de moi" crée une
  authentification persistante (cookie remember Laravel).
  L'inscription publique reste disponible tant qu'aucun administrateur
  secondaire n'existe. Une fois un second administrateur créé, l'inscription
  publique est désactivée ; les comptes sont créés par l'administrateur.
  Après login : choix de poste (/choix-poste). Si aucun poste n'existe,
  l'administrateur est redirigé vers l'initialisation du premier poste.
  Les autres utilisateurs doivent contacter un administrateur.

API (JWT)
---------
  Package : tymon/jwt-auth
  Middleware : JwtMiddleware
  Routes (prefix /api) :
    POST /api/login
    POST /api/logout
    POST /api/refresh
    GET  /api/me

Permissions (Spatie, guard web)
-------------------------------
  Alias middleware (bootstrap/app.php) :
    role, permission, role_or_permission, post.selected

  Rôles seedés :
    admin       — toutes les permissions
    chef_poste  — view + create (+ approvisionnement.confirm)
    agent       — view + create
    lecteur     — view + create

  Permissions principales :
    vehicule.* , carte_rose.* , plaque.* , post_travail.* ,
    proprietaire.* , produit.* , post_produit.* ,
    approvisionnement.* , user.* , role.manage , dashboard.global

  Seeder : database/seeders/RolePermissionSeeder.php

--------------------------------------------------------------------------------
9. FLUX MÉTIER CLÉS
--------------------------------------------------------------------------------

9.1 Création d'un véhicule
    1. Agent connecté avec poste sélectionné
    2. Formulaire véhicules/create
       - propriétaire existant OU nouveau (creer_proprietaire=1)
       - champs véhicule obligatoires : marque, type, couleur,
         immatriculation, usage
       - carte_numero optionnel (unique si fourni)
    3. VehiculesService::store
       - crée propriétaire si besoin (ou réutilise par téléphone)
       - crée véhicule + plaque + carte rose
       - consomme stock PostProduit (2 unités max, orderBy id)
    4. Redirect / message succès

9.2 Impression carte rose
    Route nommée carte.imprimer
    Permission : carte_rose.print
    DomPDF + QR (simplesoftwareio/simple-qrcode) via qr_token

9.3 Approvisionnement
    Création d'une demande / entrée
    Confirmation (chef_poste / permission confirm) met à jour le stock
    PostProduit

9.4 Première initialisation après réinitialisation de la base
    Si la table post_travails ne contient aucun poste, l'administrateur ne peut
    pas accéder au tableau de bord avant d'en créer un.
    Le formulaire /initialisation/poste crée le premier poste actif, l'associe
    à l'administrateur comme poste par défaut et le sélectionne dans la session.
    Cette étape est limitée aux comptes ayant le rôle admin et n'est affichée
    que tant qu'aucun poste n'existe.

13. CONVENTIONS DE CODE
--------------------------------------------------------------------------------

  - Controllers minces ; logique dans Services
  - Interfaces dans app/Contracts pour les services principaux
  - Réponses services souvent : ['message' => ..., 'data' => ...]
  - Orthographe métier conservée : propietaire (table + FK)
  - Valeurs vides souvent remplacées par "Non renseigne"
  - Transactions DB pour opérations multi-tables (création véhicule)
  - SoftDeletes sur Vehicule
  - Middleware permission sur chaque action sensible
  - Ne pas committer .env
